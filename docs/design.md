# EMR 감시 설계 — 2026-09-26

## 확정된 조작 범위

사람이 수술 대상 목록을 열어둡니다. 봇은 선택한 여러 진료과를 순환하며 진료의를 전체로 맞추고 조회합니다.

허용하는 입력 대상은 진료과, 진료의, 조회뿐입니다. 날짜, 수술상태, 수술방 필터, 표의 환자 행, 탭, 출력, Excel, 종료 및 기타 버튼은 조작하지 않습니다. 팝업 발생 시 자동으로 닫지 않고 감시를 중단합니다.

진료과 변경 후 진료의가 초기화될 수 있으므로 매번 전체를 확인합니다. 입력 전후 대상 창과 화면 구성을 검증하며, 식별에 실패하면 입력하지 않습니다. 사용자가 PC를 조작 중이면 감시 입력을 일시 정지하는 방식이 필요합니다.

## 현장 확인 결과

- 설치된 실행 프로세스는 XPLATFORM 9.2.1입니다.
- 목록 창에 대한 접근성 읽기는 최상위 창만 반환했습니다. 콤보박스와 표 셀을 직접 지정할 수 있다는 증거는 없습니다.
- Windows 창 캡처 도구에서 목록 창도 FrameArrived 시간 초과가 발생했습니다. 원인은 확인되지 않았습니다. 사용자가 첨부한 화면은 정상적으로 읽을 수 있습니다.
- 첨부 화면에 수술일, 진료과, 진료의, 수술상태 필터와 조회 버튼이 있습니다. 표에는 수술방, 수술순번, 시작시간, 소요시간, 진료과, 집도과, 집도의, 등록번호, 수술명 등의 열이 있습니다.
- 시작시간은 예정 시각입니다. 환자상태 글자를 비교하며 사람이 캡처로 최종 확인합니다.

## 기술 선택

권장 초안은 화면 인식 + 제한된 UI 입력 + 로컬 표 인식입니다. 고정된 절대 좌표만 사용하는 매크로는 창 이동·배율·팝업에 취약하므로 창 기준 위치와 화면 확인을 결합합니다. 현재 창 캡처 실패는 구현 전 해결할 검증 항목이며, 가능한 것으로 간주하지 않습니다.

XPLATFORM 엔진 실행 파일이나 EMR 화면 정의 파일을 직접 수정하는 방식은 채택하지 않습니다. TOBESOFT 문서의 애플리케이션 파일·Dataset·서버 연동 기능이 이 병원 EMR을 외부에서 안전하게 제어할 수 있는 API를 의미하지는 않습니다. 추후 병원에서 제공하는 공식 연동 인터페이스가 확인되면 별도로 검토할 수 있습니다.

## 감시와 분류

1. 화면의 수술일과 필터를 읽고 감시 범위로 기록합니다. 허용 범위 밖 필터가 바뀌면 기존 화면과 비교하지 않고 정지 또는 재기준 설정합니다.
2. 지정 진료과 선택 → 진료의 전체 확인 → 조회 → 로딩 완료 및 선택값 확인 → 표 인식 순서로 진행합니다.
3. 수술일·진료과별 기준을 분리합니다. 과 전환 자체가 신규 등록이나 삭제 알림을 만들지 않아야 합니다.
4. 최초 정상 결과는 기준으로만 저장합니다. 이후 변경 후보를 재확인하고 안정된 변경을 알립니다.
5. 등록번호 하나만으로 수술을 식별하지 않습니다. 같은 환자의 복수 수술과 수정 가능한 수술방·시간을 고려한 행 대응이 필요하며, 불명확하면 일반 변경으로 표시합니다.
6. 신규 행은 신규 등록, 사라진 행은 목록 이탈로 표시합니다. 사라짐을 취소나 종료로 단정하지 않습니다.
7. 실제 상태 전환을 확인할 수 있을 때만 시작·종료 알림을 만듭니다.
8. 세부 변경은 변경 항목을 묶어서 알립니다. 자동 증가하는 시간은 별도 처리합니다.
9. 인식 실패, 화면 가림, 조회 실패, 일부 행만 보이는 상태는 빈 목록으로 처리하지 않습니다. 스크롤이 필요한 목록은 현재 허용 입력 범위로 전체 감시가 가능한지 추가 확인합니다.

## 알림과 비공개 사용

주요 변경과 세부 변경에 서로 다른 제목을 사용하고, 사용자가 요청한 EMR 목록 캡처를 첨부합니다. 행 이탈은 현재 화면에서 해당 행이 없어 이전/이후 비교 방식이 필요할 수 있습니다. 수신 그룹 확정 전 실제 전송하지 않습니다.

공개 배포하지 않습니다. GitHub를 계속 사용할 경우 비공개 저장소와 내부 전달용 실행 파일을 기준으로 합니다. 환자 캡처·인식 원문·봇 토큰은 소스 관리 및 빌드 산출물에 포함하지 않습니다. 화면의 장기 보관은 기본 기능으로 추가하지 않습니다.

## 0.1.0 구현 업데이트

- 간격은 최소 30초·기본 60초이며 사용자가 설정합니다.
- 저장소는 `shinmg33/or-alert-bot`이며 비공개로 확인했습니다.
- Windows OCR, 화면 영역 수동 지정, 과별 기준, 총 건수 검증, Telegram 원본 PNG 전송을 구현했습니다.
- 설정은 DPAPI로 암호화하고 캡처는 메모리에만 보관합니다.
- 날짜는 사람이 선택한 값을 유지합니다. 자동 스크롤은 지원하지 않습니다.
- 현장 캡처·드롭다운 검증과 실제 Telegram 전송은 아직 남았습니다.
