# 수술방 알림봇 · ORAlertBot 0.2.0

Windows EMR의 수술 목록을 조회하고 변경 시 텔레그램 비공개 그룹에 화면 캡처를 보내는 내부 사용 프로그램입니다.

## 사용 순서

1. ZIP을 풀고 폴더 안의 `ORAlertBot.exe`를 실행합니다. 기존 버전은 종료해주세요.
2. **텔레그램 연결**에 BotFather 토큰을 입력하고 **연결 진단**을 누릅니다. 진단은 메시지를 보내지 않습니다.
3. 그룹에 봇을 추가하고 `/start@봇사용자이름`을 보낸 뒤 **그룹 찾기 → 그룹 선택 → 테스트 메시지 보내기**로 연결합니다.
4. 사람이 EMR 수술 목록을 열고 날짜와 필터를 설정합니다.
5. **감시** 탭에 `산부인과`, `외과`처럼 진료과 이름을 한 줄씩 입력하고 간격을 설정합니다. 최소 30초, 기본 60초입니다.
6. **감시 시작**을 누르면 EMR을 앞으로 가져와 진료과·진료의·조회와 표를 자동 인식합니다. 표나 열을 지정하거나 드롭다운 순번을 입력할 필요가 없습니다.
7. 처음에는 로컬 시험 모드로 시작합니다. 실제 과 선택과 캡처가 맞는지 확인 후 F8로 중지하고 시험 모드를 해제하면 Telegram으로 전송합니다.

감시 중 프로그램 창은 숨겨집니다. **F8**을 누르면 중지하고 설정 창으로 돌아옵니다. 화면 자동 확인과 숨겨진 위치 보정(진료과·진료의·조회 3개)은 선택 사항입니다.

## 0.2.0 변경

- 필수 화면 영역 8개·표 열 3개 지정과 확인 체크박스를 제거했습니다.
- 드롭다운 순번 대신 진료과 이름을 확인하면서 선택합니다.
- 제공받은 XPLATFORM 수술 목록의 격자선·머리글·컨트롤 이름으로 화면을 자동 찾습니다. 창 위치 이동은 자동 반영합니다.
- 행의 글자 모양을 로컬 비교합니다. 신규/사라진 행·환자상태 표시 변경은 주요 알림, 다른 항목 수정은 세부 알림입니다. 배경색만 바뀌거나 행이 재정렬된 경우를 구분합니다.
- 작은 환자상태 글자의 OCR 오독을 시작·종료로 단정하지 않습니다. ‘환자상태 표시 변경’과 전체 EMR 캡처를 보내 사람이 확인합니다.
- 원래 오류를 숨기던 Telegram 공통 오류 문구를 제거하고 원인별 코드와 해결 안내를 표시합니다.

## Telegram 오류 해결

**연결 진단**은 `getMe`로 서버·토큰을 확인한 후 `getWebhookInfo`로 기존 연동 여부를 확인합니다. 웹훅을 임의 삭제하지 않습니다.

| 코드 | 의미와 조치 |
|---|---|
| TOKEN | BotFather API 토큰 전체를 다시 입력합니다. 사용자 이름이나 앞의 `bot` 문자열을 넣지 않습니다. |
| CHAT_NOT_FOUND | 봇을 그룹에 추가하고 그룹 찾기로 Chat ID를 다시 선택합니다. |
| FORBIDDEN | 그룹 참여 여부와 메시지·파일 전송 권한을 확인합니다. |
| CONFLICT | 같은 봇을 쓰는 중복 프로그램을 종료합니다. 웹훅 충돌이면 기존 연동에서 해제하거나 Chat ID를 직접 입력합니다. |
| DNS / NETWORK / TIMEOUT | 병원 PC에서 `api.telegram.org:443` 접속 가능 여부를 확인합니다. |
| TLS_CERT / TLS | PC 시간과 병원 프록시 인증서 구성을 확인합니다. 인증서 검증을 끄지 않습니다. |
| RATE_LIMIT | 표시된 시간 후 재시도합니다. |
| MIGRATED | 화면에 표시된 새 그룹 ID를 입력합니다. |

토큰 없이 이 개발 PC에서 Telegram HTTPS 기본 접속은 확인했습니다. **사용자 토큰 인증과 그룹 전송은 별도 확인이 필요합니다.**

## 동작과 제한

- 입력 대상은 **진료과·진료의·조회**뿐입니다. 날짜·환자 행·다른 버튼·EMR 파일을 수정하지 않습니다.
- 기존에 제공된 23열 XPLATFORM 수술 목록 화면용입니다. 다른 레이아웃은 보정이 필요하며, 인식에 실패하면 추측해서 클릭하지 않습니다.
- 한국어 Windows OCR가 필요합니다. 화면 영역과 총 건수·선택 과를 읽는 데 사용하며 외부 OCR 서비스는 사용하지 않습니다.
- 처음 보는 과는 이름이 맞을 때까지 드롭다운을 탐색하므로 시간이 걸릴 수 있습니다. 실제 EMR에서 Home·방향키·Enter 선택이 작동하는지 현장 검증이 필요합니다.
- 전체 목록이 화면에 보여야 합니다. **숨겨진 행·여러 페이지·자동 스크롤은 지원하지 않습니다.** 총 건수와 행 수가 다르면 중단합니다.
- 날짜와 필터는 사람이 선택한 값을 유지합니다. 변경되면 중단합니다. 두 과·60초 설정이면 각 과는 최소 약 120초마다 확인하며 선택·인식·전송 시간만큼 늦어질 수 있습니다.
- 첫 정상 조회는 기준만 만듭니다. 두 번 확인한 결과가 일치할 때 비교합니다.
- 실제 시작은 예정 시작시간으로 추측하지 않습니다. 행 사라짐도 취소·종료로 단정하지 않습니다.
- 동일 환자의 중복 수술이나 수술명 수정은 모호한 변경으로 표시합니다. 같은 글자라도 렌더링이 바뀌면 알림이 발생할 수 있습니다.
- 소요시간 등 세부 항목은 모두 비교합니다. 자동 증가 표시가 있으면 세부 알림이 반복될 수 있습니다.
- 화면 가림·최소화·잠금·창 크기 변경·감시 중 사용자 입력 시 중단합니다. 캡처 방지 기능을 우회하지 않습니다.
- 일시적인 전송 실패는 메모리에 캡처를 보관하고 재시도합니다. 토큰·권한 등 수정이 필요한 오류는 중단합니다. 응답 유실 시 중복 수신 가능성이 있습니다.
- 중지·종료·재시작하면 기준과 미전송 캡처가 사라집니다. 이미 시작된 전송은 취소되지 않을 수 있습니다.

## 저장 및 검증

설정은 `%LOCALAPPDATA%\ORAlertBot\settings.bin`에 현재 Windows 사용자 키로 암호화합니다. 같은 계정으로 실행하는 프로그램까지 차단하는 장치는 아닙니다. 기존에 저장한 토큰·그룹은 유지됩니다.

캡처와 환자 행은 메모리에서만 처리합니다. 사용자가 요청한 대로 식별번호는 가리지 않으며 전송한 PNG는 Telegram 그룹에 남습니다. 원본 이미지를 GitHub·실행 파일에 넣지 않습니다.

첨부받은 정지 화면에서 자동 배치·선택 과·총 건수·행 감지까지 확인했습니다. **실제 EMR 자동 조회와 그룹 전송은 아직 현장 검증 전입니다.**

## 개발 및 빌드

Windows x64 + Python 3.12:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-build.txt
python -m unittest discover -s tests -v
python run.py
.\build.ps1
```

별도 Python 없이 실행 가능한 폴더형 EXE를 만듭니다. 한국어 OCR 언어팩은 별도이며 EXE는 서명되지 않았습니다.

참고: [Telegram API](https://core.telegram.org/bots/api), [Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine), [XPLATFORM](https://docs.tobesoft.com/developer_guide_xplatform_en)
