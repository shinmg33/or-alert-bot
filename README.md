# Alert Bot 0.8.0

EMR 수술 목록을 주기적으로 조회하고 변경 시 Telegram 그룹에 캡처를 보냅니다. 화면 비교 감시는 OCR 없이 동작합니다. 새 날짜·진료과 원격 선택 기능은 사용자가 지정한 버튼과 Windows 한국어 OCR로 선택값을 확인합니다. 진료의는 기존 선택을 유지합니다.

## 0.8.0 원격 조건 변경 설정

1. **조회 버튼 위치 지정**을 먼저 완료합니다.
2. **날짜·진료과 위치 지정**에서 캡처 한 장을 보며 다음 네 영역을 차례로 드래그합니다.
   - 수술일 숫자만 (예: 2026-09-28)
   - 그 옆 **캘린더 아이콘만**
   - 현재 진료과 글자 영역 (화살표 제외)
   - 진료과 오른쪽 **아래 화살표 버튼만**
3. **펼친 달력 위치 지정**을 누르고 안내창을 닫은 뒤 5초 안에 EMR 캘린더 아이콘을 직접 눌러 펼쳐둡니다. 자동 캡처된 화면에서 연월 제목, 이전 달 화살표, 다음 달 화살표, 날짜 격자를 차례로 지정합니다. 격자는 요일 줄을 제외하고 **일~토 7열 × 회색 날짜까지 6행**의 전체 셀 범위를 지정합니다. 첨부 예시와 같은 달력 구조를 지원합니다.
4. 실제 EMR의 펼친 달력을 닫고 **감시 시작/재시작**을 누릅니다.
5. Telegram에서 `/date 2026-09-29`, `/date 오늘`, `/date 내일`, `/date 어제`, `/dept 산부인과`를 사용합니다. `/help`로 명령을 확인합니다.

날짜 명령은 캘린더 아이콘 클릭 → 연월 확인 → 필요 시 월 이동 → 날짜 셀 클릭 → 수술일 확인 → 조회 → 결과 캡처 순서입니다. 현재 열린 달력에서 최대 24개월 이동합니다.

진료과 명령은 아래 화살표 클릭 → Home/방향키/Enter로 목록 선택 → 표시된 진료과 이름 확인 순서입니다. 이름은 정확히 입력하며, 스크롤 아래 항목도 순서대로 탐색합니다. 최대 200개 항목까지 지원합니다. 진료의·상태 등 다른 조건은 그대로이므로 결과 캡처에서 함께 확인하세요.

선택 실패·OCR 불확실·창 크기 변경 시 조회를 실행하지 않고 감시를 대기합니다. 일부 선택은 바뀌었을 수 있으므로 PC에서 확인하고 `/restart`로 재개하세요. 날짜·진료과 명령은 감시 중에만 접수하며 동시에 한 요청만 처리합니다. `/stop`은 대기 중인 요청을 취소하고 진행 중인 선택도 다음 확인 지점에서 중지합니다.

원격 조건 확인에는 Windows 한국어 OCR 언어팩이 필요합니다. OCR은 해당 PC에서만 수행합니다. 실제 EMR의 드롭다운 키보드 반응과 달력 배치는 현장 시험이 필요합니다.

### 넓어진 캡처

기본 전송 범위는 **EMR 상단부터 현재 보이는 마지막 행 아래 48픽셀까지, 창 전체 폭**입니다. 수술일·진료과를 함께 볼 수 있습니다. **전송 캡처 영역 지정**으로 위아래 범위를 직접 정할 수도 있습니다. 변경 비교는 계속 수술 표를 기준으로 하며 전송 영역 전체의 가림도 검사합니다.

## 사용 순서

1. 기존 봇을 종료하고 ZIP을 압축 해제한 후 `Alert Bot.exe`를 실행합니다.
2. EMR에서 진료과·진료의·날짜 등 조회 조건을 직접 선택합니다.
3. 봇에서 대상 창을 선택하고 **조회 버튼 위치 지정**을 누릅니다. 표시된 캡처에서 조회 버튼만 드래그합니다.
4. 조회 간격을 지정합니다. 최소 30초, 기본 60초입니다.
5. 텔레그램 연결 탭에서 토큰과 그룹을 설정하고 테스트 메시지로 확인합니다.
6. **감시 시작**을 누르면 첫 캡처를 즉시 전송합니다. 로컬 시험 모드는 기본 꺼짐이며 켜면 Telegram 전송과 명령 수신을 하지 않습니다.
7. F8로 중지합니다. 조회 조건을 바꾸려면 중지 후 EMR에서 변경하고 다시 시작합니다.

설정 저장 버튼으로 토큰·그룹·조회 위치를 저장할 수 있습니다. 이전 버전의 진료과 설정은 사용하지 않습니다.

## 조회 위치 다시 지정

감시 중이거나 /stop 대기 상태에서도 **조회 버튼 위치 지정**을 누를 수 있습니다. 감시를 대기시키고 로컬 캡처에서 새 위치를 선택합니다. 지정한 위치는 즉시 실행 설정과 저장 설정에 반영됩니다. **감시 재시작** 또는 `/restart`로 재개하세요.

위치 지정 중에는 원격 재시작을 보류합니다. Esc로 취소하면 기존 좌표를 유지합니다. 수동 위치 선택용 캡처에는 감시용 가림 검사를 적용하지 않으며, 다시 시작할 때 새 위치의 핵심 영역을 검사합니다.

## 화면 범위와 알림 설정

- 가림 검사는 조회 버튼, 현재 보이는 수술 표, 전송 캡처 영역을 대상으로 합니다. 대상 창이 뒤에 있어도 핵심 영역이 보이면 검사할 수 있습니다.
- 실제 표의 머리글과 행을 비교하고, 상단 조건을 포함한 넓은 캡처를 전송합니다. 새 행이 나타나면 비교 범위가 늘어납니다. 표 격자를 찾지 못한 화면은 조회 아래 영역을 비교하는 기존 대체 방식이 적용됩니다.
- 실행 모드와 알림 설정은 체크박스 대신 글자로 선택하는 메뉴입니다.
- **실제 목록 변경 알림**: 소리 알림(기본) / 무음. 신규·삭제·상태·세부 수정 모두 이 설정을 따릅니다. `[목록 변경]`으로 표시합니다.
- **시스템 안내**: 무음(기본) / 보내지 않음 / 소리 알림. 수동 중지·재시작 응답·장기 대기·종료 등의 텍스트 안내에 적용되며 `[시스템]`으로 표시합니다.
- 짧은 자동 대기·복구는 Telegram에 보내지 않습니다. 2분 이상 지속된 대기는 한 번만 알리고, 이후 복구 완료를 알립니다. 로컬 상태 표시에는 즉시 반영됩니다.
- 시작·수동 캡처는 요청대로 전송하며 기본 무음입니다. 시스템 안내를 끄더라도 요청한 캡처 자체는 전송합니다. 소리 알림은 Telegram 앱·기기의 자체 무음 설정에 따라 실제 소리가 나지 않을 수 있습니다.

## 감시 대기와 자동 복구

- 가림·최소화·창 전환·사용자 입력이 감지되어도 프로그램을 종료하지 않습니다. 감시를 대기하고 Telegram 명령 수신을 유지합니다.
- 일시적 가림이나 사용자 입력 후 **5초간 입력이 없으면** 같은 EMR 창을 복원해 앞으로 가져옵니다. 창과 크기를 다시 확인한 후 조회를 재개합니다. 복구 실패 시 5초 간격으로 재확인합니다.
- 가림 검사에서 Alert Bot이 만든 테두리 창만 제외합니다. 다른 프로그램·팝업이 실제로 가린 상태에서는 클릭하거나 캡처하지 않습니다. 원격 달력 선택 중에는 대상 EMR이 소유한 팝업을 지정한 달력 영역에서 허용합니다. EMR 팝업이나 로그인 화면을 임의로 닫지 않습니다.
- 창 크기·배율·대상 창 식별이 달라지면 수동 확인이 필요한 대기로 전환합니다. 기존 좌표로 추측해서 누르지 않습니다. 대상 창이 종료되었거나 배치가 달라졌다면 프로그램을 다시 열고 조회 위치를 지정하세요.
- 수동 대기와 장기 대기 사유는 시스템 안내 설정에 따라 Telegram에 알립니다. 네트워크 단절·프로그램 강제 종료·전원 차단 때는 전달을 보장할 수 없습니다.

## Telegram 명령

설정한 그룹에서 다음 명령을 보냅니다. 각 명령 뒤에 `@봇사용자이름`을 붙여도 됩니다.

| 명령 | 동작 |
|---|---|
| `/date YYYY-MM-DD` | 캘린더 아이콘을 눌러 날짜를 선택하고 조회 결과를 보냅니다. 오늘·내일·어제도 지원합니다. |
| `/dept 산부인과` | 아래 화살표를 눌러 정확한 이름의 진료과를 선택하고 조회 결과를 보냅니다. |
| `/help` | 명령 사용법을 보냅니다. |
| `/stop` | 감시만 정지합니다. 명령 수신은 유지하며 자동 재개하지 않습니다. |
| `/restart` | 재시작을 예약합니다. 입력이 5초 이상 없을 때 EMR을 복원하고 감시합니다. |
| `/capture` | 감시 중 현재 수술 목록을 캡처해 보냅니다. 대기 중이면 재시작 안내를 보냅니다. |

다른 그룹·개인 대화·다른 봇 대상 명령·시작 전 요청은 무시합니다. 요청은 약 2초마다 확인하며 진행 중인 HTTP 요청 때문에 지연될 수 있습니다. 동일 봇의 다른 getUpdates 프로그램이나 웹훅과 충돌하면 오류를 표시하고 다시 시도합니다. 웹훅을 삭제하지 않습니다.

## 실행 표시와 자동 종료

- 작업표시줄에 사용 중/감시 대기 상태를 표시합니다. 설정 창을 열거나 F8·중지 버튼을 누르면 수동 대기로 바뀝니다. **감시 재시작** 버튼 또는 `/restart`로 재개합니다.
- 감시 중인 EMR에는 캡처에서 제외되고 클릭을 가로채지 않는 초록 테두리를 표시합니다. 대기하면 사라지고 재개하면 다시 표시됩니다.
- **자동 종료 (시간)**: `0`은 해제, `0.5`는 30분, `8`은 8시간입니다. 대기와 `/restart`는 예약 종료 시각을 연장하지 않습니다.
- 예약 종료나 프로그램 닫기는 명령 수신도 종료합니다. 종료 알림 후 Alert Bot만 닫으며 EMR·Windows는 종료하지 않습니다. 진행 중인 HTTP 응답은 최대 20초 기다릴 수 있습니다.
- 저장된 토큰·그룹·조회 위치가 있고 EMR 창이 하나면 실행 시 자동 시작합니다. 첫 캡처를 보내며 시험 모드에서는 전송과 명령 수신을 하지 않습니다.
- 배포 폴더의 `create-shortcut.ps1`로 바탕화면 바로가기를 만들 수 있습니다.

## 변경 감지

- 시작 직후 현재 EMR 캡처를 전송합니다. 첫 안정된 조회 결과는 비교 기준으로 저장하며 이후 2초 간격의 두 캡처가 일치할 때 변경을 비교합니다.
- 수술 표 격자가 인식되면 표 영역을 비교합니다. 행 추가·삭제·환자상태 변경은 주요, 기타 수정은 세부로 분류합니다.
- 표 구조나 행 분류가 불가능해도 중단하지 않습니다. 조회 버튼 아래 화면 또는 감지된 표를 비교하고 일반 변경 알림과 전체 EMR 캡처를 보냅니다.
- 분류는 보조 정보입니다. 실제 시작·종료는 예정시각으로 추측하지 않습니다.
- 현재 보이는 화면만 감시합니다. 숨겨진 행·다른 페이지·다른 진료과를 순회하지 않습니다.
- 화면 렌더링이나 자동 증가하는 시간이 바뀌어도 알림이 발생할 수 있습니다.
- 최소화·가림·사용자 입력은 복구 대기로 전환합니다. 크기가 바뀌면 조회 위치를 다시 지정합니다.
- 일시적 전송 실패는 메모리의 캡처를 재시도합니다. 전송 성공 후 비교 기준을 갱신합니다. 응답 유실 시 중복 알림이 가능하며 종료하면 미전송 캡처는 사라집니다.

## Telegram 오류 해결

**연결 진단**은 `getMe`로 서버·토큰을 확인한 후 `getWebhookInfo`로 기존 연동 여부를 확인합니다. 웹훅을 임의 삭제하지 않습니다.

| 코드 | 의미와 조치 |
|---|---|
| TOKEN | BotFather API 토큰 전체를 다시 입력합니다. 사용자 이름이나 앞의 `bot` 문자열을 넣지 않습니다. |
| CHAT_NOT_FOUND | 봇을 그룹에 추가하고 그룹 찾기로 Chat ID를 다시 선택합니다. |
| FORBIDDEN | 그룹 참여 여부와 메시지·파일 전송 권한을 확인합니다. |
| CONFLICT | 같은 봇을 쓰는 중복 프로그램을 종료합니다. 웹훅 충돌이면 기존 연동에서 해제하거나 Chat ID를 직접 입력합니다. |
| DNS / NETWORK / TIMEOUT | 병원 PC에서 `api.telegram.org:443` 접속 가능 여부를 확인합니다. |
| TLS_CERT / TLS | PC 시간과 병원 프록시 인증서 구성을 확인합니다. 인증서 검증을 끄지 않습니다. |
| RATE_LIMIT | 표시된 시간 후 재시도합니다. |
| MIGRATED | 화면에 표시된 새 그룹 ID를 입력합니다. |

토큰 없이 이 개발 PC에서 Telegram HTTPS 기본 접속은 확인했습니다. **사용자 토큰 인증과 그룹 전송은 별도 확인이 필요합니다.**

## 저장 및 개발

설정은 `%LOCALAPPDATA%\ORAlertBot\settings.bin`에 Windows 사용자 키로 암호화합니다. 환자 캡처는 메모리에서만 처리하며 GitHub와 EXE에 포함하지 않습니다. Telegram으로 전송된 이미지는 그룹에 남습니다.

Windows x64 + Python 3.12에서 `pip install -r requirements-build.txt`, `python -m unittest discover -s tests -v`, `python run.py`로 개발 실행합니다. `build.ps1`로 폴더형 EXE와 ZIP을 생성합니다.

실제 병원 EMR 조회와 Telegram 그룹 전송은 현장 확인이 필요합니다.
